# Code Comment Auto Remediation

本文件只在发现源码注释事实候选后读取，用于判断 `code-comment-fact` 是否可进入 `DOC-*` 自动修复。它不授权修改可执行代码，也不授权重写注释表达。

---

## 允许范围

候选必须属于以下事实之一：

- **机械引用**：注释中的符号名、文件路径、URL、版本号、配置键或命令已经机械过期；
- **局部实现事实**：注释中的内部常量、默认值、重试次数、超时时间、内部组件名或实现机制已经变化。

机械引用须由当前真实定义唯一证明。局部实现事实须同时由本轮 diff 和任务规划、测试结果或其它已读取权威证据证明本次变化是预期行为，不能只因代码与注释不同就假定注释错误。

修复只替换目标事实片段，保留原语言、语气、标点和周边内容；不整句润色、不删除注释，也不顺带修复相邻措辞。

## 禁止范围

以下注释即使含有过期事实也不得自动修改：

- 公共 API 的 Javadoc/docstring、对外契约、业务或安全语义、解释 Why 的设计理由；
- lint/type-ignore、pragma、构建标签、shebang、许可证头或工具消费的指令；
- TODO、FIXME、HACK、负责人、期限或尚未完成的工作承诺；
- doctest、可执行示例、复制后会执行的命令块或测试夹具；
- 无法把事实片段与判断、承诺或行为语义分离的注释。

## 执行边界

- subagent 只返回候选，不得写入工作区。
- interactive 与 validated auto-loop 的主会话都可以落地，但必须先满足本文件和事实漂移总规则。
- 源码注释修改不得传给 `--doc-remediation-file`；该参数仍只绑定当前任务实际修改的 `implement.md` 与 `brief.md`。

## 修复后验证

每次写入后必须：

1. 重读最终注释和相邻实现，确认只替换目标事实片段；
2. 重新计算实际 diff 和检查范围；
3. 复核 `check_profile`，行为或影响面扩大时升级 full；
4. 重跑受影响的无副作用定向验证，并在 `DOC-*` 结果中记录证据。
